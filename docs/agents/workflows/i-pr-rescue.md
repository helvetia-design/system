# Workflow I — PR rescue (merge conflicts)

**One agent, one job:** bring a PR branch up to date with its base and resolve conflicts without
changing what the PR does.

```text
PR / branch
  →  orchestrator: confirm worktree is the PR branch, clean tree, fetch
  →  component-engineer · resolving-merge-conflicts   (merge origin/<base>, resolve in the tree)
  →  ds-validate-component  on the conflicted files' components only
  →  ⛔ human completes the merge commit and pushes
```

**Rules**

- **Merge, don't rebase,** unless the human says otherwise: no history rewrite on a shared branch.
- **Union, don't pick a side.** Both sides' intent survives: imports, test blocks, doc comments,
  changesets. A conflict where the two sides contradict is a question for the human, not a guess.
- **No agent commits or pushes** (see `ds-team.md`). The resolved tree is left for the human to
  finish with `git merge --continue` and push.
- **Generated files** (`components.d.ts`, Angular `generated/*`, `components.json`) are
  regenerated by the build, never hand-merged.
- **Changesets:** a conflict in `.changeset/*` keeps both entries; severity unchanged.
- **Validate narrowly:** typecheck plus the play suites of the components that had conflicts.
  A broken suite after the merge is reported with its output, never weakened.
- Report: files conflicted, how each resolved (one line), what was validated, what was not.

Escalate to the orchestrator when a conflict touches an ownership line (e.g. tokens + component);
the owning agent resolves its own files.
