**This skill never commits**

## Requirements

- [Claude Code](https://www.anthropic.com/claude-code)
- An app that already has `@baloise/ds-*` installed
- Angular apps need a major version the Helvetia packages support — the skill checks and tells you

## Install

```bash
npx @helvetia-design/skills add
```

Run it in your repository root, and re-run it any time to update.

## Use

```
/ds-migrate-from-baloise
```

Five entries, best run in order:

1. **Init** — installs the `@helvetia-design/*` packages and imports next to your `@baloise/*` ones. Nothing is removed, so both run side by side and your app keeps working.
2. **Components** — migrates `bal-*` to `ds-*`. One component, the ones it detects, or a whole folder.
3. **CSS utils** — rewrites legacy utility and `css/core` classes, then removes the Baloise utilities import.
4. **Assets** — migrates leftover icons, moves fonts and favicons, removes the legacy config call.
5. **Cleanup** — removes the legacy imports and `@baloise/ds-*` dependencies. Refuses while anything is still unmigrated.

## How a migration runs

The **Components** step offers three modes for identifying which components to migrate:

- **Manual** — pick one migration and run it everywhere.
- **Detect** — suggests what it finds in use, with counts, plus a `not yet` list of what it cannot cover.
- **Scope** — every `bal-*` component in the files or folders you name. Suits most migrations: components nest, and a migrated container around an unmigrated child breaks quietly, so a batch migrates them together and takes the containers first.

Whichever mode you pick, the run has four phases:

1. **Scan** — lists every usage with file, line and snippet.
2. **Confirm** — asks before editing. Nothing has changed yet.
3. **Rewrite** — applies the mapping. Anything it cannot map safely is left alone and reported.
4. **Report** — appends to `ds-migration-report.md` and prints what needs you.

## The report

`ds-migration-report.md` grows with every phase. **Needs your attention** holds the decisions only you can make — a prop with no equivalent, a missing accessible name, a test selector that no longer matches. **Coverage** records what was handled automatically. The file is part of the unstaged diff and is committed with the rest of the changes.
