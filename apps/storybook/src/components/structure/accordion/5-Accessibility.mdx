## Structure

Each accordion is self-contained: a heading that wraps a native `button` with `aria-expanded` and `aria-controls`, plus a content region labelled by that button. Enter and Space toggle it through the native button. There is no arrow-key navigation between accordions and no `aria-multiselectable`; Tab moves from one summary to the next.

### Heading level

The summary is rendered as a heading, and `summary-level` defaults to `h3`. Set it to match the outline of your page, for example `h2` below an `h1`, so heading levels never skip. For nested accordions, use one level deeper than the parent accordion. Check this on every page, since the default only fits some layouts.

## Grouping accordions

Accordions next to each other do not announce that they belong together. Pick the first option that fits, in this order.

### 1. A heading above

A visible section heading above the accordions gives screen reader users the outline for free. Choose `summary-level` one level below it.

```html
<h2>Frequently asked questions</h2>
<ds-accordion summary-level="h3" group="faq">
  <span slot="summary">How do I calculate the sum insured?</span>
  <p slot="content">...</p>
</ds-accordion>
<ds-accordion summary-level="h3" group="faq">
  <span slot="summary">Which belongings are covered?</span>
  <p slot="content">...</p>
</ds-accordion>
```

### 2. `ds-list` when the count matters

Wrap each accordion in an `li` inside `ds-list`, with `list` on the accordion. Screen readers then announce "list, N items", which helps for an FAQ where the number of rows matters. See the List section on the [Variants](?path=/docs/components-structure-accordion-variants-overview--overview) page.

```html
<ds-list>
  <li>
    <ds-accordion list group="faq">
      <span slot="summary">How do I calculate the sum insured?</span>
      <p slot="content">...</p>
    </ds-accordion>
  </li>
  <li>
    <ds-accordion list group="faq">
      <span slot="summary">Which belongings are covered?</span>
      <p slot="content">...</p>
    </ds-accordion>
  </li>
</ds-list>
```

`list` is incompatible with `button` and the `button*`, `summaryTitle` and `summaryVisualLevel` props. If combined, `list` wins visually.

### 3. `role="group"` only without a visible heading

If there is no visible heading, wrap the accordions in an element with `role="group"` and give it an accessible name with `aria-labelledby` (or `aria-label`).

```html
<div role="group" aria-label="Frequently asked questions">
  <ds-accordion summary-level="h3">...</ds-accordion>
  <ds-accordion summary-level="h3">...</ds-accordion>
</div>
```

Never use `role="region"` for the group. Each accordion content already renders as its own `role="region"`.

## Conformance

This page describes the patterns the component supports. It does not claim WCAG 2.2 AA conformance, and no per-criterion verification for the accordion, including the `list` and `inverted` looks, is linked here yet. The `inverted` look on the Base brand has been checked with axe and computed contrast: 16.37:1 for text and 12.36:1 for the focus ring on a primary surface. Other brands, states and the remaining criteria are not covered by that check.
